# 安卓端 Work 模型适配设计

## 目标

在保留现有定制 Flutter 安卓客户端视觉设计、离线能力和阅读器体验的前提下，使其完整适配 YMReader 服务端的 `Work → WorkUnit → Comic` 数据模型，并继续兼容旧缓存与旧服务器链接。

## 产品范围

本次只改安卓客户端与服务端的读取、导航和进度对接，不修改漫画文件、NAS 书库、服务端数据库或容器挂载。

核心用户流程：

1. 用户在首页按“全部／具体书库”浏览作品级封面墙。
2. 用户进入作品详情页，查看作品级元数据、刮削封面和有序目录。
3. 用户从立即阅读、继续阅读或目录进入阅读器，并可使用目录、上一话、下一话及作品级阅读模式记忆。

非目标：

- 不恢复旧“合集”产品逻辑。
- 不重新设计现有客户端主题和主要视觉风格。
- 不删除离线书架、PDF、小说和旧链接兼容能力。
- 不修改服务端 Work API。

## 当前问题

现有 Flutter 客户端的主要页面仍以 `/comics` 和 `/groups` 为数据源：

- 首页会按实体漫画文件展示，章节可能重新散落。
- “合集”和“按文件夹收起”与当前服务端 Work 模型重复。
- 继续阅读按实体 `comicId` 聚合，而非按作品聚合。
- 详情页无法稳定使用作品级元数据、封面和目录。
- 阅读器只知道实体漫画文件，缺少 `workId` 与 `unitId` 上下文。
- 搜索、收藏、标签和书库筛选与 Web 端作品级结果不一致。

## 数据模型

### Work

安卓端新增与服务端 `/api/works` 对齐的 `Work` 模型，保存：

- 作品 ID、书库 ID、标题、作者、简介和刮削元数据。
- 作品封面、封面宽高比、收藏、评分和阅读状态。
- 总页数、单元数量、继续阅读目标。
- 有序 `WorkUnit` 列表。

### WorkUnit

每个目录项保存：

- `unitId`
- `workId`
- 实体 `comicId`
- 显示名称
- 排序位置
- `startPage`
- `pageCount`
- 单元封面和阅读记录

实体 `comicId` 只负责页面、PDF或小说内容读取；作品展示和导航均以 `workId` 为主键。

## API 适配

新增独立 `WorkApi`，不把 Work 请求继续塞入旧 `ComicApi`：

- `GET /works`
- `GET /works/:id`
- `GET /works/:id/units`
- `PUT /works/:id/favorite`
- `PUT /works/:id/rating`
- `PUT /works/:id/reading-status`

首页、搜索、收藏和继续阅读统一请求 `/works`。具体页面仍通过原有 `/comics/:id/pages`、PDF和小说接口读取实体内容。

客户端启动后进行轻量能力检测：支持 `/works` 时使用 Work 模式；旧服务器或离线旧缓存继续使用 legacy 模式，避免已有离线内容失效。

## 页面与导航

### 首页

- 隐藏“合集”和“按文件夹收起”。
- 使用作品级海报墙，不混入 WorkUnit 或实体章节。
- 顶部使用横向书库切换：全部、日漫、国漫及其他服务端书库。
- 封面优先使用 Work 的刮削封面。

### 搜索、收藏和继续阅读

- 搜索结果按 Work 返回，一部漫画只出现一次。
- 标签、分类和收藏筛选使用 Work API。
- 继续阅读使用 `continueComicId`、`continueUnitId` 和 `continuePage`。
- 封面和标题始终来自 Work，不从实体章节反推。

### 作品详情

- 新增 Work 详情路由 `/work/:id`。
- 保留现有详情页的视觉层级和立即阅读／继续阅读按钮。
- 目录按 `sortIndex` 排序，显示 `displayLabel`。
- 旧 `/comic/:id` 与 `/group/:id` 路由保留为兼容入口，但不再出现在首页主流程。

### 阅读器

阅读路由增加可选参数：

- `workId`
- `unitId`
- `page`

阅读器继续按实体 `comicId` 加载图片，但通过 Work 上下文完成：

- 目录定位。
- 上一话、下一话。
- 跨话继续阅读。
- 返回作品详情页。
- 作品级阅读进度与继续阅读目标。

没有 Work 上下文的离线内容和旧链接仍保持当前行为。

## 每部作品阅读模式记忆

使用本地存储，以 `work:<workId>` 为键保存：

- 单页、双页或长条模式。
- 阅读方向。
- 首页独显。
- 双页贴合。
- 页面适配。
- 连续阅读。

没有 Work ID 时回退到 `comic:<comicId>`。预加载数量、亮度等通用设置继续保持全局。

## 上游更新策略

当前分支已经包含上游 `v1.0.16`，上游最后一次 Flutter 改动来自 `v1.0.14`。本次不覆盖现有定制客户端。

以后同步上游时：

1. 先比较 `flutter_app` 范围的提交。
2. 只吸收与离线、渲染、认证、性能和平台兼容相关的改动。
3. Work 数据层、导航和页面逻辑以本项目实现为准。
4. 每次合并必须运行模型、路由、API 合同和阅读器回归测试。

## 测试与交付

自动测试覆盖：

- Work 与 WorkUnit JSON 解析。
- Work 查询参数。
- 作品级继续阅读目标。
- 阅读路由构造和解析。
- 上一话、下一话和目录排序。
- 作品级阅读设置隔离。
- legacy 回退。

交付门槛：

- `flutter analyze` 无错误。
- `flutter test` 全部通过。
- Release APK 构建成功。
- 使用现有签名配置签名。
- 提升应用版本号，支持覆盖安装。
- APK 输出到固定发布目录并提交代码到 `ymreader-final`。
